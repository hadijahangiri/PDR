# خلاصه مستند نیازمندی‌های محصول (PRD)
# پلتفرم اطلاعات گل و گیاه ایران

**نام ویژگی:** پلتفرم جامع اطلاعات گل و گیاه ایران  
**نسخه:** 1.0  
**تاریخ:** 1404/11/13  

---

## 📋 خلاصه اجرایی

یک پلتفرم مدیریت محتوای جامع برای ایجاد منبع اصلی دیجیتال اطلاعات گل و گیاه به زبان فارسی در ایران. این سیستم محیطی همکارانه فراهم می‌کند که در آن مدیران پلتفرم را اداره کرده و نویسندگان مقالات گیاه‌شناسی با قابلیت‌های سئو کامل تولید می‌کنند.

---

## 🎯 اهداف اصلی

1. **منبع معتبر:** ایجاد بزرگترین مخزن آنلاین محتوای گیاه‌شناسی به زبان فارسی
2. **کیفیت محتوا:** تضمین کیفیت از طریق گردش کار ساختاریافته بررسی و تایید
3. **بهینه‌سازی سئو:** جذب ترافیک ارگانیک از موتورهای جستجو
4. **دسترسی آسان:** رابط کاربری ریسپانسیو برای همه دستگاه‌ها
5. **جستجوی قوی:** موتور جستجوی داخلی برای دسترسی سریع به اطلاعات

---

## 👥 نقش‌های کاربری

### 1. مدیر سیستم (Administrator)
**مسئولیت‌ها:**
- ✅ مدیریت کاربران (ایجاد، ویرایش، غیرفعال‌سازی)
- ✅ تایید/رد مقالات جدید نویسندگان
- ✅ تایید/رد ویرایش‌های مقالات موجود
- ✅ مدیریت نظرات (تایید/رد/ویرایش)
- ✅ ایجاد و ویرایش مقالات بدون نیاز به تایید
- ✅ مشاهده آمار و گزارش‌های سیستم

### 2. نویسنده (Writer)
**مسئولیت‌ها:**
- ✅ ایجاد مقالات جدید (نیاز به تایید مدیر)
- ✅ ویرایش هر مقاله موجود در سیستم (نیاز به تایید مدیر)
- ✅ مشاهده تاریخچه ویرایش‌های خود
- ✅ مشاهده نظرات روی مقالات خود
- ✅ مشاهده آمار نوشتاری (تعداد مقاله، نرخ تایید)

### 3. بازدیدکننده عمومی (Public Visitor)
**امکانات:**
- ✅ خواندن مقالات منتشر شده
- ✅ جستجوی مقالات با موتور جستجوی داخلی
- ✅ گذاشتن نظر روی مقالات (پس از تایید مدیر نمایش داده می‌شود)

## 🔑 ویژگی‌های کلیدی

### مدیریت مقالات
- ✍️ ایجاد، ویرایش، حذف مقالات با ویرایشگر متنی پیشرفته
- 📸 آپلود چندین تصویر برای هر مقاله
- 🏷️ دسته‌بندی مقالات (گل‌ها، درختان، درختچه‌ها، گیاهان دارویی، ساکولنت‌ها و...)
- 🔖 برچسب‌گذاری با برچسب‌های از پیش تعریف شده و سفارشی
- 📝 نسخه‌برداری و تاریخچه کامل ویرایش‌ها

### قابلیت‌های سئو (SEO)
- 🔗 URL سفارشی برای هر مقاله (slug)
- 📋 متا تایتل، متا دیسکریپشن، کلمات کلیدی
- 🗺️ تولید خودکار XML Sitemap
- 🌐 Open Graph tags برای اشتراک‌گذاری در شبکه‌های اجتماعی
- ✅ URL‌های سئو-دوست با ساختار مناسب

### گردش کار تایید (Approval Workflow)

#### برای مقالات جدید نویسندگان:
1. نویسنده مقاله جدید ایجاد می‌کند
2. مقاله با وضعیت "در انتظار بررسی" ذخیره می‌شود
3. مدیر نوتیفیکیشن دریافت می‌کند
4. مدیر مقاله را بررسی و تایید/رد می‌کند
5. نویسنده نوتیفیکیشن نتیجه را دریافت می‌کند

#### برای ویرایش مقالات موجود:
1. نویسنده مقاله موجود را ویرایش می‌کند
2. سیستم یک "نسخه ویرایش" (Revision) ایجاد می‌کند
3. نسخه ویرایش با وضعیت "در انتظار بررسی" ذخیره می‌شود
4. مدیر مقایسه side-by-side از تغییرات را می‌بیند
5. مدیر تغییرات را تایید/رد می‌کند
6. اگر تایید شود، تغییرات روی مقاله اصلی اعمال می‌شود

### مدیریت نظرات
- 💬 ثبت نظر توسط بازدیدکنندگان
- ⏳ همه نظرات ابتدا در حالت "در انتظار تایید" قرار می‌گیرند
- ✅ تایید/رد/ویرایش نظرات توسط مدیر
- 🛡️ فیلتر اسپم برای جلوگیری از نظرات مزاحم
- 💭 نمایش تعداد نظرات هر مقاله

### موتور جستجو
- 🔍 جستجوی تمام متن در عنوان، محتوا و برچسب‌ها
- 🇮🇷 پشتیبانی کامل از متن فارسی با توکنایزیشن مناسب
- 📊 رتبه‌بندی نتایج بر اساس ارتباط
- 🎯 فیلترهای جستجو (دسته‌بندی، محدوده تاریخ، نویسنده)
- 💡 پیشنهاد جستجو (autocomplete)
- 📄 صفحه‌بندی نتایج

### طراحی ریسپانسیو
- 📱 موبایل: 320px - 767px
- 📱 تبلت: 768px - 1024px
- 💻 دسکتاپ: 1025px به بالا
- ◀️ پشتیبانی کامل از RTL برای فارسی
- 🖼️ تصاویر ریسپانسیو با اندازه‌های مناسب
- ✋ المان‌های لمسی با اندازه مناسب (44x44px)

## 🏗️ معماری فنی

### پشته فناوری (Tech Stack)
- **Backend:** ASP.NET Core (C#)
- **Authentication:** Identity Server
- **Database:** SQL Server
- **Frontend:** Razor Pages یا MVC با Bootstrap/Tailwind
- **Image Storage:** File System یا Azure Blob Storage
- **Search:** SQL Server Full-Text Search یا Elasticsearch

### API Endpoints اصلی

#### احراز هویت
- `POST /api/auth/login` - ورود کاربر
- `POST /api/auth/logout` - خروج کاربر
- `POST /api/auth/refresh` - تمدید توکن

#### مقالات
- `GET /api/articles` - لیست مقالات
- `GET /api/articles/{id}` - جزئیات مقاله
- `POST /api/articles` - ایجاد مقاله (فقط مدیر)
- `PUT /api/articles/{id}` - ویرایش مقاله

#### نسخه‌های ویرایش
- `GET /api/revisions` - لیست نسخه‌های ویرایش
- `GET /api/revisions/{id}` - جزئیات نسخه ویرایش
- `POST /api/revisions/{id}/approve` - تایید نسخه (فقط مدیر)
- `POST /api/revisions/{id}/reject` - رد نسخه (فقط مدیر)

#### نظرات
- `GET /api/articles/{articleId}/comments` - لیست نظرات مقاله
- `POST /api/comments` - ثبت نظر جدید
- `PUT /api/comments/{id}/approve` - تایید نظر (فقط مدیر)
- `PUT /api/comments/{id}/reject` - رد نظر (فقط مدیر)

#### کاربران
- `GET /api/users` - لیست کاربران (فقط مدیر)
- `POST /api/users` - ایجاد کاربر (فقط مدیر)
- `PUT /api/users/{id}` - ویرایش کاربر (فقط مدیر)

#### جستجو
- `GET /api/search` - جستجوی مقالات

## 📊 نیازمندی‌های غیر-عملکردی

### عملکرد (Performance)
- ⚡ زمان بارگذاری صفحه: کمتر از 2 ثانیه
- 🔍 زمان پاسخ جستجو: کمتر از 500 میلی‌ثانیه
- 👥 پشتیبانی از 1000 کاربر همزمان
- 📤 آپلود تصویر: کمتر از 5 ثانیه برای فایل‌های 5 مگابایتی

### امنیت (Security)
- 🔒 استفاده از HTTPS برای همه ارتباطات
- 🔐 هش کردن رمزهای عبور با bcrypt
- 🛡️ محافظت در برابر XSS و SQL Injection
- ⏱️ Rate limiting برای جلوگیری از حملات brute force
- 📝 لاگ کردن همه رویدادهای امنیتی

### قابلیت اطمینان (Reliability)
- ✅ 99.5% uptime در ساعات کاری
- 💾 پشتیبان‌گیری روزانه خودکار
- 📁 نگهداری پشتیبان‌ها برای 30 روز
- 🚨 هشدار برای خطاهای حیاتی

### دسترسی‌پذیری (Accessibility)
- 🌐 پشتیبانی کامل از فارسی با رندرینگ RTL
- ♿ رعایت استانداردهای WCAG 2.1 Level AA
- 🎨 کنتراست رنگ مناسب (حداقل 4.5:1)
- ⌨️ امکان ناوبری با کیبورد

## ⚠️ ریسک‌های اصلی

### ریسک 1: کیفیت محتوای نویسندگان
**توضیح:** نویسندگان ممکن است محتوای بی‌کیفیت یا نادرست ارسال کنند.

**راه‌حل:**
- فرآیند بررسی دقیق با کارشناسان گیاه‌شناسی
- ارائه راهنمای نوشتاری و استانداردهای محتوا
- آموزش نویسندگان
- دوره آزمایشی برای نویسندگان جدید

### ریسک 2: گلوگاه در تایید ویرایش‌ها
**توضیح:** حجم بالای ویرایش‌های در انتظار ممکن است مدیران را غرق کند.

**راه‌حل:**
- استخدام تعداد کافی مدیر
- اولویت‌بندی صف بررسی
- تعیین SLA برای بررسی (مثلاً 48 ساعت)
- چک‌های خودکار کیفیت

### ریسک 3: پیچیدگی جستجوی فارسی
**توضیح:** زبان فارسی گرامر و مورفولوژی پیچیده دارد.

**راه‌حل:**
- استفاده از کتابخانه تخصصی جستجوی فارسی
- تست کامل با کاربران فارسی‌زبان
- ارائه راهنمای جستجو به کاربران

## ✅ معیارهای پذیرش (Acceptance Criteria)

### عملکرد اصلی
- [ ] مدیر می‌تواند مقالات را ایجاد، ویرایش و حذف کند
- [ ] مدیر می‌تواند چندین تصویر برای هر مقاله آپلود کند
- [ ] مدیر می‌تواند متادیتای سئو را تنظیم کند
- [ ] نویسنده می‌تواند مقالات جدید ایجاد کند (وضعیت: در انتظار بررسی)
- [ ] نویسنده می‌تواند مقالات موجود را ویرایش کند (ایجاد نسخه ویرایش)
- [ ] مدیر می‌تواند نسخه‌های ویرایش را مقایسه و تایید/رد کند
- [ ] تاریخچه کامل ویرایش‌ها ثبت و نگهداری می‌شود

### مدیریت کاربران
- [ ] مدیر می‌تواند حساب کاربری ایجاد کند (مدیر یا نویسنده)
- [ ] مدیر می‌تواند حساب‌ها را غیرفعال کند
- [ ] سیستم دسترسی‌های مبتنی بر نقش را اعمال می‌کند
- [ ] Identity Server احراز هویت را انجام می‌دهد
- [ ] الزامات رمز عبور قوی اعمال می‌شود

### مدیریت نظرات
- [ ] بازدیدکنندگان می‌توانند نظر ثبت کنند
- [ ] همه نظرات ابتدا "در انتظار تایید" هستند
- [ ] مدیر می‌تواند نظرات را تایید/رد کند
- [ ] فقط نظرات تایید شده نمایش داده می‌شوند
- [ ] فیلتر اسپم فعال است

### جستجو
- [ ] جستجو برای متن فارسی نتایج مرتبط برمی‌گرداند
- [ ] نتایج بر اساس ارتباط رتبه‌بندی می‌شوند
- [ ] فیلتر بر اساس دسته‌بندی و برچسب کار می‌کند
- [ ] صفحه‌بندی نتایج (20 آیتم در هر صفحه)

### سئو
- [ ] هر مقاله URL slug یکتا دارد
- [ ] متا تگ‌ها در HTML head ظاهر می‌شوند
- [ ] XML sitemap خودکار تولید می‌شود
- [ ] Open Graph tags موجود است
- [ ] ساختار URL بهینه است

### ریسپانسیو
- [ ] صفحات روی موبایل صحیح نمایش داده می‌شوند
- [ ] صفحات روی تبلت صحیح نمایش داده می‌شوند
- [ ] صفحات روی دسکتاپ صحیح نمایش داده می‌شوند
- [ ] متن فارسی به درستی RTL است
- [ ] تصاویر برای اندازه‌های مختلف مقیاس‌بندی می‌شوند

### عملکرد
- [ ] صفحات مقاله در کمتر از 2 ثانیه بارگذاری می‌شوند
- [ ] جستجو در کمتر از 500ms پاسخ می‌دهد
- [ ] سیستم 1000 کاربر همزمان را پشتیبانی می‌کند

### امنیت
- [ ] همه ارتباطات از HTTPS استفاده می‌کنند
- [ ] رمزهای عبور با bcrypt هش می‌شوند
- [ ] محافظت CSRF فعال است
- [ ] ورودی‌ها sanitize می‌شوند
- [ ] rate limiting فعال است
